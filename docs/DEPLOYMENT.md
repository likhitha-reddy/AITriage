# Deployment on Render

This project ships with a Render Blueprint in `render.yaml` that provisions the backend API, AI triage service, and PostgreSQL database.

## 1. Create a Render account

1. Sign in to [Render](https://render.com/).
2. Make sure your GitHub account can access this repository.

## 2. Connect the GitHub repository

1. In Render, choose **New +** > **Blueprint**.
2. Connect the `AITriage` repository.
3. Select the `main` branch.
4. Render will detect `render.yaml` at the repository root.

## 3. Deploy with the Blueprint

1. Review the resources Render plans to create:
   - `aitriage-db` (PostgreSQL)
   - `aitriage-backend` (FastAPI backend)
   - `aitriage-ai` (AI triage service)
2. Provide a value for `CORS_ORIGINS` during the initial Blueprint flow.
3. Confirm the deploy.

### Manual setup alternative

If you do not want to use Blueprints:

1. Create a free PostgreSQL instance named `aitriage-db`.
2. Create a Docker web service named `aitriage-ai` from the `ai` root directory using `ai/Dockerfile`.
3. Create a Docker web service named `aitriage-backend` from the `backend` root directory using `backend/Dockerfile`.
4. Set the environment variables from the table below.
5. Deploy both services from the `main` branch.

## 4. Set environment variables

### Required values

| Service | Variable | Required | Source / Example |
| --- | --- | --- | --- |
| backend | `DATABASE_URL` | Yes | Render PostgreSQL connection string from `aitriage-db` |
| backend | `JWT_SECRET` | Yes | Generated by Blueprint (`generateValue: true`) |
| backend | `AI_SERVICE_URL` | Yes | Render internal host:port for `aitriage-ai` |
| backend | `CORS_ORIGINS` | Yes | Comma-separated frontend origins, e.g. `https://your-frontend.example.com` |
| backend | `RENDER` | Yes | `true` |
| backend | `ENVIRONMENT` | Recommended | `production` |
| backend | `DEBUG` | Recommended | `false` |
| backend | `CREATE_TABLES_ON_STARTUP` | Recommended | `false` |
| ai | `OPENAI_API_KEY` | Required for OpenAI provider | Store in the `aitriage-ai-secrets` Render environment group |
| ai | `ANTHROPIC_API_KEY` | Required for Anthropic provider | Store in the `aitriage-ai-secrets` Render environment group |
| ai | `LLM_PROVIDER` | Yes | `openai` or `anthropic` |
| ai | `MODEL_NAME` | Yes | `gpt-4.1-mini` |

### Notes

- The backend accepts both `JWT_SECRET` and `JWT_SECRET_KEY`; Render uses `JWT_SECRET` in the Blueprint.
- The backend normalizes Render internal service hostnames such as `aitriage-ai:8001` into full HTTP URLs automatically.
- The backend also normalizes Render-style Postgres URLs if they are provided as `postgres://...`.
- Render free instances do not support true private services. In this setup, `aitriage-ai` runs as a free web service and the backend uses its internal network address.

## 5. Set up PostgreSQL

1. Let the Blueprint create `aitriage-db`, or create it manually.
2. Use Render's internal database connection string for `DATABASE_URL`.
3. The backend startup entrypoint runs Alembic migrations when revision files exist.
4. If the database does not yet contain reference data, the backend seeds doctor and subscription plan records automatically.

## 6. Deploy

1. Trigger the initial Blueprint deploy.
2. Wait for all services to become healthy.
3. On subsequent pushes to `main`, Render auto-deploys both web services.

## 7. Verify the deployment

Check the following health endpoints after deploy:

- Backend: `https://<backend-service>.onrender.com/health`
- AI service: `https://<ai-service>.onrender.com/health`

The backend health response should return `status: ok`.
The AI health response should return `status: ok` and reflect the configured provider/model.

## Troubleshooting

### Backend fails to connect to Postgres

- Confirm `DATABASE_URL` points to the Render Postgres instance.
- If the URL starts with `postgres://`, redeploy after confirming the latest backend image is running; the app now normalizes that format.
- Check Render logs for migration or connection errors.

### AI requests fail from the backend

- Confirm `AI_SERVICE_URL` points to the Render internal host/port for `aitriage-ai`.
- Verify the AI service is healthy at `/health`.
- Ensure the AI service and backend are deployed from the same Blueprint.

### AI service reports no provider configured

- Add `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` to the `aitriage-ai-secrets` environment group.
- Ensure `LLM_PROVIDER` matches the provider whose key you supplied.

### CORS errors in the frontend

- Set `CORS_ORIGINS` to every deployed frontend origin, separated by commas.
- Redeploy the backend after changing origins.

### Seed data does not appear

- Check backend logs for the startup entrypoint output.
- The seed step only runs when doctor/subscription reference tables are empty.
- Re-run a deploy after confirming the database is reachable.
